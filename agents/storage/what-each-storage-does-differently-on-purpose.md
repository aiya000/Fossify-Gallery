# ストレージごとに、わざと違えてあること

## おこったこと

3つのストレージ（端末・pCloud・共有）は順に増えたので、機能ごとに「次のストレージまで伸ばした
ところ」がまちまちでした。#107 で全部読み直して、「決めごと」「抜け」「未決」に分けました。
抜けは直しています（#107 のコメントに一覧）。

ここに書くのは**決めごと**です。コードを読んだときに「共有だけ無いのは忘れているのでは」と
思っても、ここに載っていれば**わざと**です。直す前にこの紙を読んでください。

## 決めごと（2026-09-23 時点）

| こと | どう違う | なぜ |
|---|---|---|
| 複数まとめて名前変更（メディアも、フォルダも） | 端末だけ | リモートの API は1件ずつ。`canRenameSeveral` / `canRenameSeveralFolders` |
| 隠す（先頭ドット） / ショートカット | 端末だけ | どちらも端末のファイルシステムの話。リモートのフォルダは設定（`pCloudHiddenFolders` / `smbHiddenFolders`）で隠す。`canHide` / `canCreateShortcut` |
| 除外フォルダ | 端末だけ | 除外は端末パスの仕組み。リモートは「隠す」で足りる。`canExcludeFolders` |
| 動画を取ってから見る（download videos） | 共有だけ | 共有だけストリーミング再生なので、先に手元へ置く道がある。`streamsVideos` |
| 動画をシステムのプレイヤー / ジェスチャープレイヤーで開く | 端末だけ | リモートの動画はアプリ内で流す。他のプレイヤーはファイルを欲しがる |
| 「動画をダウンロード」「動画の長さを読む」のメニュー | 共有が設定されていれば**全フォルダ**に出る | 見えたり消えたりする理由が分からないより、「0件」と答えるほうがいい（コードのコメント参照） |
| 開いたときの自動再スキャンの間隔 | pCloud はフォルダごと、共有は共有全体 | 共有は1フォルダ1リクエストで、いつ歩いたかの列を持たない |
| 書き込み後の再スキャン | pCloud はフォルダを読み直す、共有は歩かない | 共有の書き込みは行を持ち回る。共有を歩くと分単位かかる |
| 同じ名前があるとき | 名前変更: 断る / コピー・移動: 連番 / Save as・リサイズ: 聞いて上書き | ユーザーが打った名前かどうか |
| pCloud → 共有への直接コピー・移動 | 出ない（それ以外の組は全部出る） | 端末を経由しないと運べない（#28）。`canTransferTo` |
| 一時フォルダ（新しく作って空のまま戻ったとき） | 端末は消す、pCloud は一覧から外すだけ | アプリはリモートのフォルダを勝手に消さない |
| 「撮影日を EXIF から直す」 | 端末だけ | 要るかを聞いたが、ふだん使わないメニューだったので今のまま。要るなら `fetchForReading` で EXIF は読める |
| フォルダのプロパティ（合計サイズ・件数） | 端末だけ | 同上。要るなら行から組み立てられる（メディア1件は #60 でそうした） |

## 次に気をつけること

- **新しい分岐を足すときは、`MediaStorage` の capability に載せること。** 画面が `isPCloudPath()` で
  分岐すると、共有が置いていかれる（#107 の抜けは全部この形だった。`isRemote` か型の答えを読む）
- 決めごとを変えたら、この表とその capability のコメントを両方直すこと
- 「抜け」だったものと、その直しかたは #107 のコメントにある。ここには書かない
