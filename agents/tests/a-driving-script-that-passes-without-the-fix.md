# 画面を見るテストが、直しを外しても緑だった

## おこったこと

`test-device/drive/` の台本を書いて、直したアプリで緑になりました。
念のため直しを外してビルドし直し、同じ台本を走らせたら -- **それも緑でした**。

つまりその台本は、何も確かめていませんでした。

## 原因

タイルに絵が入っているかを、**色のばらつき（標準偏差）**で測っていました。

直しの片方（Picasso へ渡さない）が入ったことで、失敗したタイルには
**黄色い警告アイコン**が描かれるようになっていました。
黒い背景に黄色いアイコンは、ばらつきとしては立派な「絵」です。

「読み込みに失敗しました」と言っているタイルを、「絵が出ている」と数えていたわけです。

## したこと

測りかたを、**1色がタイルの何割を占めるか**に変えました。

- プレースホルダだけ -- その色が10割
- プレースホルダ＋警告アイコン -- それでも9割以上
- ほんとうのサムネ -- 1色はごく一部

しきい値は6割です（`test-device/drive/thumbs.py` の `DOMINANT`）。

## 次に気をつけること

- **端末を動かす台本は、必ず「直しを外した版」でも走らせてください**
    - ビルドし直して入れ直すぶん、数分よけいにかかります
    - それでも、確かめていないテストを持ち続けるほうがずっと高くつきます
- **画面から読み取るテストは、「何も無い」と「失敗したと言っている」を区別してください**
    - アプリはたいてい、失敗したときに何かを描きます
    - その何かを、成功と数えないようにするのです
- JVM のテストでも同じです。わざと壊して赤くなるのを見るまで、緑は信じないのです
